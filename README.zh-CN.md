# Agent Relay：本地与云端 Agent 的 Git 任务接力

用一个私有 Git 仓库传递 Markdown 任务单，不共享会话，也不让模型定时空转。
默认本地只做纯拉取、由用户主动接手；安装可选执行器后，写了
`- Executor:` 的本地任务可自动领取并派发，形成双向自动接力。

这是供 Agent 阅读、辅助用户搭建整套流程的参考实现，不是一键托管服务，
也不意味着所有平台都已实测。把项目交给自己的 Agent，让它先读 README、
协议及两端安装说明，再结合实际环境提出并执行获准的安装步骤。
用户仍需提供仓库访问权限、云端运行环境、Webhook 凭据及必要的操作批准。

- 本地交云端：新增任务 → GitHub Actions → Webhook 唤醒云端。
- 云端交本地：新增任务 → Mac 每 300 秒纯 Git 拉取。
  - 默认：用户主动让本地 Agent 接手。
  - 可选：安装 `relay-runner` 后，带 `- Executor:` 的 pending 任务自动领取并派发；
    未写该字段的任务仍保持手动接手。
- 往返任务：任务单写 `- Receipt: required` 时，接收方完成后另写一份回执
  （本地完成写 `tasks/receipts/to-cloud/`，云端完成写 `tasks/receipts/to-local/`）。
  云端收到回执事件后接续；本地可用可选的 `receipt-notify` 定时器弹通知，不启动模型。
  回执不是任务单，不携带新权限。
- 状态和结果写回原单；文件送达不等于已接手，已接手不等于完成。

## 安装入口

按 [英文首页](README.md) 的步骤准备独立任务仓库，再看
[Mac 安装](docs/setup-local-macos.md)、
[Grok 云端接入](docs/setup-cloud-grok.md) 和
[任务协议](docs/protocol.md)。

公开的是工具、协议与模板，不是用户的真实任务。任务仓库建议保持私有。
两端技能都叫 agent-relay，分别安装 local 或 cloud 版本，不要装错角色。

公共版使用英文元数据字段，例如 `- Status: pending`；
与旧私人部署的中文字段不直接兼容。现有系统不要覆盖升级，
先在独立仓库验证。

安装时可用 `--with-runner` 额外安装执行器，用 `--with-receipt-notify` 额外安装
只读的回执提醒（只弹 macOS 通知，不 fetch、不提交、不调用模型）；不加参数时
仍只有纯拉取定时器。卸载用 `bash scripts/macos/uninstall.sh`。

## 双向自动接力

本地→云端在任务推送后由 Webhook 自动唤醒云端，这条链路原本就是自动的。
云端→本地默认仍由纯拉取定时器送达、用户主动接手；只有额外安装执行器后，
本地才会自动执行明确写了以下字段的任务：

```markdown
- Executor: paseo
- Role: <可选的本地角色预设名>
- Target directory: /绝对路径
```

- 执行器默认不安装，安装时用 `--with-runner` 显式开启；必须先跑
  `RELAY_RUNNER_DRY_RUN=1` 验证。
- 只有状态 `pending` 且 `- Executor:` 与本地配置匹配的任务会被领取；
  `accepted`、`done`、`blocked` 一律不自动重跑。
- 目标目录必须绝对、存在且在本地白名单内；角色或 provider 不可用时任务标为
  `blocked`，不会替换成别的角色或 provider。
- 执行器本身不 fetch/pull，也不会在脏工作区、分支不对、领先/分叉或有任务锁时动手。
- 一次只派发一个任务。执行器同步等待被派 Agent 结束，先记录本地执行证据，
  再只接受这一个任务的终态、复核回执一致并推送它扫描过的那一个提交；
  结果未知或失败时保留现场并写 `PAUSED`，仅删除 `PAUSED` 不构成推送授权。
- 发布、删除、部署、改权限、对外发送等高风险动作只准备不执行，等用户明确授权。
- 执行器是真实执行路径，不是沙箱；仍受宿主机权限与审批约束。

### 安全防护

执行器内置三层“失败即拦截”的防护（详见 [docs/security.md](docs/security.md)）：

1. **目标目录白名单**：原始路径含 `..` 直接拒绝；解析软链接后的真实路径必须在任务仓库内、
   （不含其 `.git`）、`RELAY_WORKSPACE_ALLOWLIST` 列出的目录内，或 `RELAY_PROJECTS_ROOT` 下已存在的一级项目目录内。
2. **任务单正文扫描**（认领后、派发前）：除执行器自行校验的元数据字段行外的全部正文（含 `- Task:`、`- Constraints:` 等）
   命中 `.ssh`、私钥、`.env`、Keychain、凭据/token 赋值、`curl -F`/`scp` 上传等敏感模式时，
   任务直接标为 `blocked`，不启动执行者，日志不回显原文。普通的“token 数量”不会误报。
3. **结果出口检查**（`RELAY_GUARD_WAIT=1`，唯一支持的模式）：执行者只 commit 不 push，
   执行器同步等待其结束，再逐提交、逐 blob 扫描将要推送的内容（含提交元数据；大文件与二进制默认拒绝），
   干净才推送那个确切的提交；命中则写入 `PAUSED` 暂停标记，不推送任何内容。

## 使用方式

- “把这个任务交接给云端／本地”：目标与权限清楚后正式交出。
- “先生成任务单给我看看”：只在聊天起草，不写正式目录、不推送。
- “看看交过来了什么任务，别接手”：只查看。
- “接手任务 <ID>”：先记录领取，再执行。
- “恢复任务 <ID>”：先核对中断现场，不盲目重跑。
- “安装／卸载本地自动执行器”：属于配置变更，需用户明确授权。

Mac 定时脚本不执行任务、不提交、不推送；休眠或同步跳过时，
不保证五分钟内到达。脚本遇到无关修改、领先提交或锁占用会保留现场。
可选执行器只领取明确 opt-in 的任务，且不代删任何锁。

云端采用独立 checkout，由 Agent 精确提交，不依赖私人环境里的
全工作区自动提交脚本。Grok 的 Webhook、权限与技能发现需按当前产品界面配置，
新安装仍需实测。已验证与未验证范围见 [validation](docs/validation.md)。

公开测试中的执行器使用假执行器和临时仓库，回执提醒测试使用假通知程序，
都不是真机端到端集成测试。
